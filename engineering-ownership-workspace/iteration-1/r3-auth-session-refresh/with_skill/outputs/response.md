이 변경은 production 인증 흐름을 바꾸므로 **R3**입니다. 빠르게 구현할 수는 있지만, 코드 생성만으로 merge-ready라고 판단하지는 않겠습니다.

현재 사용자 의도는 “production 로그인에 rotating refresh token을 도입해 탈취된 토큰의 재사용 범위를 줄인다”로 보존하겠습니다. 저장소를 연결하면 기존 brief/ADR와 인증 책임 모듈, 토큰 저장·폐기 정책, 로그인/로그아웃 흐름을 먼저 찾겠습니다. 기록이 없다면 다중 기기 정책, 동시 갱신 허용 범위, 재사용 감지 시 토큰 패밀리 폐기 범위, 기존 세션 호환성과 같은 제약 및 사용자의 초기 접근/불확실점만 짧게 확인하겠습니다.

구현 전에 상세 brief와 결정 기록, 위협 모델, 운영 runbook을 검토 가능하게 만들겠습니다. 설계에는 토큰 회전의 원자성, replay 탐지, 동시 요청 경쟁, 저장소 침해, 로그아웃/강제 폐기, 관측 신호, 단계적 적용과 롤백을 포함하고 대안의 trade-off를 사용자와 결정하겠습니다.

구현 후에는 현재 diff에 묶인 새 검증만 증거로 사용합니다. 회전·만료·토큰 패밀리 폐기 단위 테스트, DB/API 경계 통합 테스트, 실제 로그인→갱신→로그아웃 경로, 경쟁·저장소 장애·replay 실패 주입과 복구 리허설을 실행 승인 후 확인하고 전체 diff를 검토하겠습니다. 마지막으로 사용자가 AI의 답을 받지 않고 데이터 흐름, 선택한 설계와 기각한 대안, 실패 관측, 검증, 롤백을 설명해야 합니다. 그 teach-back을 제가 대신 통과 처리하지 않으며, 이 게이트와 단계적 배포 준비가 끝나기 전에는 merge-ready라고 말하지 않겠습니다.
